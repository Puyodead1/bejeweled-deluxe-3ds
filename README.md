# Bejeweled Deluxe for Nintendo 3DS

Homebrew port of Bejeweled Deluxe 1.87 (PopCap, 2007) to the Nintendo 3DS, built with devkitPro (devkitARM +
libctru + citro3d), ported from the [Bejeweled Deluxe decomp](https://github.com/Puyodead1/bejeweled-decomp) by way
of the Switch port (`bejeweled-deluxe-nx`), whose history this repository continues. The plan is `3DS_PORT.md` in the
decomp repository.

**Status: phase 8 (console testing).** `bejeweled.3dsx` runs on an Old 3DS: title screen, loading (about 10.5 s;
5 s in Azahar), a game played by touch, saving and continuing, the HOME menu. The screen is drawn by the GPU with
citro3d: about 2-3 ms of drawing and 0.5 ms of presenting per frame on the console, so the frame rate is whatever
the game redraws (40-70 fps in play). The phase 3 software renderer is still there for comparison and draws at about
5 fps in Azahar.
## Renderers

The game draws into a 640x480 screen image, the way it drew into a DirectDraw surface on Windows, in one of two
ways:

- **GPU (default).** `C3DInterface`, the 3DS counterpart of the 1.87 `D3DInterface`: every image the game draws to
  the screen gets textures (power-of-two pieces up to 1024x1024; RGB565 for images without alpha, RGBA4 when the game
  asks for it, otherwise RGBA8), and blits, stretches, rotations, fills, lines and polygons become batched,
  CPU-clipped triangles drawn into a 1024x512 render target that keeps its pixels between frames, so only dirty
  widgets are redrawn.
- **Software.** The framework's own blitters draw into a plain ARGB image, which the GPU's DMA engine copies into a
  texture each frame. Chosen by creating the file `sdmc:/3ds/Bejeweled/software-renderer` (any contents).

Either way the result is drawn on both screens (see the controls). The `perf:` lines in
`sdmc:/3ds/Bejeweled/bejeweled.log`, every 10 s, give the frame rate and draw/present times, the GPU renderer's
draw calls, vertices, texture uploads and texture memory, and how often the game found something to redraw.

## Controls

| 3DS | Game |
| --- | --- |
| Touch | the mouse: tap a gem then its neighbour, or drag one onto the other |
| A | start from the title screen; yes / OK on a dialog |
| B | no / back out of a dialog |
| X | hint |
| Y | pause; play again after game over |
| SELECT | options |
| L / R | top screen: title art, close-up or whole picture (remembered) |
| START | quit (the game in progress is saved) |

Touch is the only pointer; there is no cursor. The bottom screen is the game, the whole picture at half size. The top
screen has its own picture: the title art, without the loading bar and "tap here", which stay on the bottom screen.
That's all it shows on the title screen; in play, L or R steps it through two more views and back, and the choice is
saved with the settings:
- a full-size close-up that glides to the open dialog (Options, Quit, game over...) or, with no dialog open, to the
  last touch;
- the same whole picture as the bottom screen.

The Options sliders are dragged by touch, and the name dialog opens the system keyboard by itself (tap the name field
to open it again).

## Saves and the system

Everything lives in `sdmc:/3ds/Bejeweled/`: settings (`registry.dat`), high scores, the game in progress
(`userdata/savegame.dat`), screenshots and the log. Files are written to a `.tmp` and then moved into place, and an
interrupted move is finished (or an unfinished write dropped) at the next start, so a crash or a pulled SD card
leaves the previous save rather than a broken one.

- **Quitting** (START, Quit Game, or Close from the HOME menu, or the power button) saves the game in progress, as
  on the PC; the next start asks whether to continue it.
- **HOME menu and sleep** pause the game and mute it. Before the app is suspended the settings and the game in
  progress are saved, in case the console is switched off from the HOME menu or its battery runs out while asleep.
  That save is dropped again on return, so a game that later ends isn't offered to continue.
- **High score names** are typed on the system keyboard; **fatal errors** show the system error screen.
- On a New 3DS the game runs at 804 MHz and loads its data on the extra core.

## Layout

| Path | Contents |
| --- | --- |
| `src/game/` | Game code (board, gems, dialogs, app class) |
| `src/framework/` | SexyAppFramework, ImageLib and PakLib as shipped in 1.87, with the Switch port's gcc fixes |
| `platform/3ds/` | 3DS platform layer: `CtrPlatform` (APT, input, threads, keyboard), `CtrAudio` (NDSP), `CtrRegistry`, `win32compat.h`, the sprite shader, the smoke test |
| `res/` | `.3dsx` icon (48x48, from the 1.87 exe's icon) |
| `tools/` | Data packing, emulator run and screenshot scripts |
| `romfs/` | Game data, generated by `tools/pack_data.ps1` (not checked in) |

## Requirements

- devkitPro with 3DS support at `C:\devkitPro` (or set `DEVKITPRO_WIN`), plus, from `C:\devkitPro\msys2\usr\bin`:
  `pacman -S 3ds-libmodplug 3ds-libpng 3ds-libjpeg-turbo 3ds-zlib 3ds-libvorbisidec 3ds-libogg`
- An installed copy of Bejeweled Deluxe 1.87 (the game data isn't included).
- For sound on a console: the DSP firmware dumped to `sdmc:/3ds/dspfirm.cdc` (DSP1). Without it the game runs silent.
- Optional: the [Azahar](https://azahar-emu.org) emulator for testing.

## Building

```powershell
.\tools\pack_data.ps1 -GameDir 'J:\SteamLibrary\steamapps\common\Bejeweled Deluxe'   # once: copy data into romfs\
.\build.ps1                     # -> build\bejeweled.3dsx, build\smoke.3dsx
.\build.ps1 -Debug              # -> build-debug\
.\build.ps1 -Clean              # rebuild everything
```

`build.ps1` runs CMake inside the devkitPro msys2 shell, because devkitPro's CMake toolchain refuses Windows-native
CMake. Game data is packed into the `.3dsx`'s RomFS with lowercase paths (RomFS is case-sensitive and the game's own
paths aren't consistent).

## Smoke test

`smoke.3dsx` draws a 640x480 frame (the title screen background, gems from the gem sheet, a translucent and an
additive bar) into an off-screen render target and shows it on both screens: the bottom screen gets the whole frame
at half size, the top screen the same or, after L/R, a 1:1 window that follows the pointer. Music
(`1984-network.s3m`) streams through libmodplug; A or a tap plays `select.ogg`. Touch puts a red marker under the
stylus, the Circle Pad and d-pad move the white pointer, START quits. It logs to `sdmc:/3ds/Bejeweled/smoke.log`,
including a `perf:` line every 5 s (frame rate, CPU/GPU time per frame, music decode cost, free memory).

## Running

In Azahar:

```powershell
.\tools\run_azahar.ps1 -Azahar <Azahar folder> -App build\bejeweled.3dsx -Log bejeweled.log -Seconds 30 -Shot shot.png
```

It starts Azahar with the app, waits, saves a screenshot of the window, closes Azahar and prints the log from
`%APPDATA%\Azahar\sdmc\3ds\Bejeweled\`. On a console, copy the `.3dsx` to `sdmc:/3ds/` and start it from the
Homebrew Menu, or send it with `3dslink build\bejeweled.3dsx` while the Homebrew Menu waits for it (press Y).
