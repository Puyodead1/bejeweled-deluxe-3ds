# Bejeweled Deluxe for Nintendo Switch

Homebrew port of Bejeweled Deluxe 1.87 (PopCap, 2007) to the Nintendo Switch, built with devkitPro (devkitA64 +
libnx) and SDL2. The game and SexyAppFramework sources come from the reconstructed 1.87 source in the
BejewledDeluxe decomp repo; this repo is Switch-only, so the Windows/DirectX code is free to be replaced.

See [PLAN.md](PLAN.md) for the port plan and status.

## Layout

| Path | Contents |
| --- | --- |
| `src/game/` | Game code (board, gems, dialogs, app class) |
| `src/framework/` | SexyAppFramework, ImageLib and PakLib as shipped in 1.87 |
| `third_party/` | zlib 1.1.3, libpng 1.0.5, IJG libjpeg 6b, Tremor (PopCap's copies) |
| `platform/switch/` | Switch platform layer (for now: the phase 1 smoke test `hello.cpp`) |
| `res/` | `.nro` icon |
| `tools/` | Data packing, emulator run and screenshot scripts |
| `romfs/` | Game data, generated by `tools/pack_data.ps1` (not checked in) |

## Requirements

- devkitPro with Switch support at `C:\devkitPro` (or set `DEVKITPRO_WIN`), plus
  `pacman -S switch-sdl2 switch-libmodplug` from `C:\devkitPro\msys2\usr\bin`.
- An installed copy of Bejeweled Deluxe 1.87 (the game data isn't included).
- Optional: the [Eden](https://eden-emu.dev) emulator for testing (`eden-cli.exe`, found via `EDEN_DIR` or
  `~\Downloads\eden`).

## Building

```powershell
.\tools\pack_data.ps1 -GameDir 'J:\SteamLibrary\steamapps\common\Bejeweled Deluxe'   # once: copy data into romfs\
.\build.ps1                     # -> build\hello.nro
.\build.ps1 -Debug              # -> build-debug\
.\build.ps1 -Clean              # rebuild everything
```

`build.ps1` runs CMake inside the devkitPro msys2 shell, because devkitPro's CMake toolchain refuses Windows-native
CMake. Game data is packed into the `.nro`'s RomFS with lowercase paths (the Switch file system is case-sensitive and
the game's own paths aren't consistent).

## Running in Eden

```powershell
.\tools\run_eden.ps1 -Nro build\hello.nro -Seconds 30 -Shot shot.png
```

It starts `eden-cli`, waits, saves a screenshot of the window, closes Eden and prints the app's log from
`%APPDATA%\eden\sdmc\switch\Bejeweled\`. On hardware, copy the `.nro` to `sdmc:/switch/` and start it from the
Homebrew Menu (title-override / full RAM mode recommended).

The game logs to `sdmc:/switch/Bejeweled/bejeweled.log` (pass `-Log bejeweled.log`). Eden doesn't fault on wild
pointers, it logs every unmapped access to `%APPDATA%\eden\log\eden_log.txt` and crawls on; check there when the game
seems to hang. `tools\gdb_eden.ps1` runs the game under gdb through Eden's gdbstub (see the comment at its top).

For scripted runs, `-AutoInput script.txt` installs a script of timed taps, drags, controller buttons, stick moves,
"make the hinted move" and in-game screenshots (format in `SexyAppBase::LoadAutoInput`), and `-Shots dir` collects
the screenshots afterwards:

```powershell
.\tools\run_eden.ps1 -Nro build\bejeweled.nro -Seconds 30 -Log bejeweled.log -AutoInput play.txt -Shots shots
```
